#### 1. Dependencies Added
- `io.jsonwebtoken:jjwt-api:0.12.6`
- `io.jsonwebtoken:jjwt-impl:0.12.6`
- `io.jsonwebtoken:jjwt-jackson:0.12.6`

- Uses BCrypt hash: `$2b$12$kOKLxSvI4YxowaksUvZqFuhNXWOrlYE40A5QUVEnBOPMj8DKfQLA6`

#### 3. Authentication Components

**AuthController** (`/auth/token`)
- Public endpoint for user login
- Accepts email and password
- Returns JWT token and user information

**AuthService**
- Validates credentials using BCrypt
- Generates JWT tokens with userId, email, and role

**JwtUtil**
- Generates JWT tokens with 24-hour expiration
- Validates and extracts claims from tokens
- Uses HMAC-SHA256 signing algorithm

#### 4. Configuration
Added to `application.yml`:
```yaml
jwt:
  secret: ${JWT_SECRET:distrischool-jwt-secret-key-change-in-production-minimum-256-bits-for-HS256}
  expiration: ${JWT_EXPIRATION:86400000} # 24 hours
```

### API Gateway Changes

#### 1. JWT Filter
**JwtAuthenticationFilter**
- Global filter that validates JWT tokens on all requests
- Excludes public endpoints:
  - `/api/v1/auth/**` (login)
  - `/actuator/health`
  - `/actuator/info`
- Returns 401 Unauthorized for invalid/missing tokens

#### 2. Routing
Added auth route:
```yaml
- id: auth-service
  uri: http://user-service:8080
  predicates:
    - Path=/api/v1/auth/**
  filters:
    - StripPrefix=2
```

## Frontend Implementation

### 1. Authentication Context (`AuthContext.jsx`)
- Manages authentication state globally
- Provides `login()`, `logout()`, `isAuthenticated()`, `hasRole()` functions
- Stores JWT token and user data in localStorage

### 2. Protected Routes (`ProtectedRoute.jsx`)
- Wraps protected pages
- Redirects unauthenticated users to `/login`
- Supports role-based access control

### 3. Login Page (`Login.jsx`)
- Clean, modern login form
- Calls `/api/v1/auth/token` endpoint
- Stores token and user data on success
- Redirects to dashboard after login

### 4. API Service Updates (`api.js`)
- Automatically injects JWT token in Authorization header
- Handles 401 responses by clearing auth data and redirecting to login

### 5. Header Component
- Displays logged-in user name and role
- Provides logout button
- Clears auth data and redirects to login on logout

### 6. Navigation Component
- Shows "Usuários" link only for ADMIN role
- All other links visible to all authenticated users

## Security Features

### 1. Password Security
- Passwords stored using BCrypt hashing
- Salt automatically generated by BCrypt
- Never stored in plain text

### 2. Token Security
- JWT tokens signed with HMAC-SHA256
- 24-hour expiration
- Secret key should be changed in production (via JWT_SECRET env var)

### 3. API Security
- All API routes protected by default
- Public endpoints explicitly whitelisted
- Invalid tokens result in 401 Unauthorized

### 4. Frontend Security
- Tokens stored in localStorage (consider httpOnly cookies for enhanced security)
- Automatic redirect on 401 responses
- Protected routes prevent unauthorized access

## Role-Based Access Control (RBAC)

### Roles
- **ADMIN**: Full system access, can manage users
- **TEACHER**: Access to teaching features
- **STUDENT**: Access to student features
- **TECHNICAL_ADMIN**: Access to administrative features

### Current Implementation
- Navigation menu adapts based on user role
- "Usuários" management only visible to ADMIN
- Future: Backend endpoints should enforce role-based authorization

## Known Limitations

1. **Token Storage**: Tokens are stored in localStorage, which is vulnerable to XSS attacks. Consider using httpOnly cookies.
2. **No Refresh Tokens**: Users must re-login after token expiration.
3. **Backend Authorization**: Currently only frontend enforces role-based access. Backend endpoints should also validate roles.
4. **No Account Recovery**: No password reset or account recovery mechanism.
5. **No Session Management**: No way to invalidate tokens or manage active sessions.
